## 流程

1. `python index.py`：建「中文名 → 合集包 uuid」索引（`index.json`）和 `gear_index.json`。来源是汉化译文（英文原名 → 中文名）、PFWiki 条目/页面、全维基英文索引（`zh-build/src/enindex.py`）。汉化译文重新生成后要重跑。
2. `python audit.py`：把全部属性块解析成建造计划（`data\Data\zh-monsters\plans_all.json`），同时统计缺什么（`audit.json`）。`python plan.py [英文名 ...]` 只出指定几只（`plans.json`）。
3. 旧译名对照（只在缺口变多时重做）：`python shortlist.py` 给每个没对上的名字配 10 个候选、切成 `work/*.json`；交给子代理挑（结果 `aliases_out/*.json`）；`python merge_aliases.py` 合成 `aliases/<组>.json`（plan.py 读）和补充条目清单。
4. `python supplement.py` → `supplement.json`；GM 页面里 `(await import('/zh-monsters/build_actor.js?v='+Date.now())).syncSupplement()` 建补充合集包（条目 id 由键名算出，`supp_ids.py`，两边一致；清单里没有的会删掉）。
5. 整批：GM 页面里

   ```js
   const b = await import('/zh-monsters/batch.js?v=' + Date.now());
   b.runAll();                       // 全部；或 b.runAll({ only: ["怪物图鉴2"] })
   ```

   逐本：建角色（世界里「批量（临时）」文件夹）→ 每把攻击正式使用核对（投掷武器、弹药用掉的数量会还原）→ 清空并导入该书的合集包 → 删临时角色。进度在 `window.__run`。单只调试仍可用 `m.buildAll([plan], folderId)`（`res[i].bad` 为空 = 数值与属性块一致，`res[i].log` 是补了什么、什么没对上）。

## 统一的做法

- 专长、法术、天生攻击（啮咬、爪抓……）、怪物能力（通用怪物规则、不死特性……）、种族生命骰、职业、武器盔甲，一律从 pf1 / pf-content 合集包复制同一条目，带 `_stats.compendiumSource`；复制出来的是 Babele 翻译后的中文版。
- 数值让 PF1 自己算：种族生命骰按类型选（强弱豁免对不上时先改进度），HP 调种族生命骰/职业的 hp，技能按等级填（本职 +3 已考虑），剩下的差值写进一个名为「属性块修正」的能力（删掉它就能看到系统原始计算）。
- 攻击按正式使用（`item.use`）核对：次要天然攻击的 -5 和力量减半由系统扣，补差时已算进去。持武器时天然攻击一律算次要。
- 武器标精制品/破损；不死生物的 HP 和强韧用魅力。

## 第二轮整理（2026-10-16）

- **通用怪物规则词条**：维基页里 `<noinclude>`（「X 是一条通用怪物规则」导语、类型标签）和 `<includeonly>`（嵌入用标题框）都不进描述，只留正文和「格式」行，开头加一行「类型：Ex 或 Su；位置：……」。改在 `zh-build/src/build.py` 的 `transclusion_body`，所有合集包同步生效。

- **法术书**：照系统自带怪物的写法，关掉自动法术位计算，每环次数按属性块手填，学派额外位设 0，勾上「忽略属性限制」。类法术能力用准备模式，每日次数记在「已准备」上，随意/恒定标随意施展。不再出现「属性值不足」「已知 +N」「+1 学派」。
- **特殊能力**：描述依次从本属性块、同页其他属性块（成年龙的能力写在总条目里）、怪物绪论、CHM 中英对照找到的通用规则里取；都没有时放属性块原文那一行。没对上通用规则的，按名字关键词从 Foundry 核心图标库（`icons/magic`、`icons/creatures`）挑图标（`extras.py` 的 `ICON_KEYS`）。
- **免疫拆分**：免疫 → 伤害免疫（能量类型）和状态免疫（PF1 的 conditionTypes），抗力 → 能量抗力，弱点 → 易伤，伤害减免 → 结构化（类型、「或/和」）；拆不了的写进对应栏的自定义文字。认不出的感官（龙感、降雪视觉）放进感官的自定义栏。
- 攻击补差：破损武器的 -2 和次要天然攻击一样只在正式使用时扣，已算进去。

### 第五轮补丁（2026-10-17，全量跑完后发现的）

- **HP 写成「183（15 HD；4d10+11d10+101）」**（写了 HD 数、骰子有好几种）原来解析不出生命骰，58 只 HP 成了 0；现在先认「N HD」，没有就把骰子数加起来。
- **职业行**：旧译名「盗贼→游荡者、圣武士→圣骑士、反圣武士→反圣骑士、骑士→骑将、枪手→铳士、变形师→法师」；去掉「德鲁伊等级5」里的「等级」、「魔战士 UM9」里的出处缩写；等级后面跟「（」也认。类人生物带职业时种族生命骰 = 总 HD − 职业等级（战蜥人野蛮人 8 = 2 种族生命骰 + 8），不再一律当 0。
- **装备索引**：「弩矢」原来被「弩矢（grappling）」（精制品）先占，弩的攻击都多 1。`index.py` 先记完整中文名，去掉括注的名字最后补，括注正好是该物品英文名的优先。
- **攻击对上不能攻击的物品**（铁链、炼金物品）时改为自建攻击。
- 改完后全部 3646 只重建一次。`batch.js` 另有 `fixup([{name, source}])` 只重建几只、替换合集包里的同名条目。批量跑时页面每分钟把进度写到 `progress.json`、把逐只的数值/攻击问题写到 `results.json`（页面自己刷新过一次，详细结果丢了，所以加了这个）。
- **重复的物品标识符**（Foundry 报「发现重复的物品标识符 classFeat_loreMaster / ex / su」）：两个原因。
  1. 物品没有标识符时 PF1 按名字生成，中文名里的汉字被丢掉，「全局视野（Ex）」「毒素（Ex）」都成了 `ex`，带次数的能力因此互相覆盖资源。现在 `build_actor.js` 的 `assignTags` 给能力和攻击按英文名生成标识符（没有英文名用中文名散列，同名加编号）。已导入的用 `retag.js` 直接改合集包里的标识符，不动数值。
  2. 职业物品创建时按 `classAssociations` 自动带上职业特性，和属性块里已建的那条重复。现在建职业前就把属性块已有的从关联清单里去掉，`dedupeClassFeatures` 也按标识符去重（只看职业特性）。已导入的有这类重复的用 `fixup` 重建。比较标识符不分大小写（我们按英文名生成的是 `scribeScroll`，职业特性里是 `ScribeScroll`）；同一只怪里两条同标识符的（两个技能专攻）后一条加编号。
  - 2026-10-17 修复：`retag.js` 改了 3620 只的 19119 个标识符；有职业特性重复的 350 只（野性认同、免除材料、林地步、耐力、抄写卷轴……）重建。
  - 攻击「徒手打击」和武僧的同名职业特性标识符一样：攻击的加 `Attack`（只比能力，不然武僧的职业特性会被当成重复去掉）。
  - 剩下约 20 只的同标识符是系统本来的样子，没有次数、不报警：两个职业都给的特性（游荡者 + 影舞者各一份直觉闪避，术士 + 吟游诗人各一份戏法），以及术士/法师职业自己同时带的「施法免材」「抄写卷轴」职业特性和专长。
- **神话道途不是职业**：「大法师 6」（Archmage）按后缀被认成法师 6 级（老巫师贾特比、芭芭雅嘎），`plan.py` 已跳过。
- **`fixup` 同名**：同一出处有 12 对同中文名的（路霸 = Street Thug / Highwayman），只按中文名会重建错的那只；现在可以传 `{name, source, en}`。

### 第六轮：种族、技能专攻、奖励专长、武器、能力分栏（2026-10-17）

- **种族**：每只怪都有种族物品（PF1 的生物类型、子类就挂在种族上）。
  - 核心种族里有的用 `pf1.races` 的条目：职业行写了种族（「人类 战士 4」「男性半精灵平民 1」），或属性块本身就是这个种族（大地精、灰矮人）。生物类型要对得上，人类巫妖是不死生物，不用人类。语言清空（照属性块）。
  - 否则这个怪物自己就是种族（树精的种族是树精、类型精类）：带职业的取职业前的种族词（巨魔战士 → 巨魔），龙去掉年龄（古红龙 → 红龙），其余去掉体型（大型火元素 → 火元素）、去掉「动物伙伴：」「魔宠：」。不带任何修正。
  - 子类按属性块：用词和系统不同的有对照表（跨位面 = 异界、水栖 = 水生、福使 = 盖丁天族……），系统没有的（豺狼人、沼蜍人）写成自定义。
  - 种族的体型和速度会盖过角色上的，所以都照属性块填；种族的能力调整（精灵敏捷 +2）、增强腰带之类由 `fixAbilities` 把基础值往回调，总值等于属性块。
- **技能专攻**：合集包条目不带修正。按括注的技能加 `ifelse(gte(@skills.X.rank, 10), 6, 3)`（`plan.py` 的 `skill_specs` 解析「察觉」「知识〔历史〕」「专业［商人］」）；推技能等级时多调一轮（10 级起 +6）。原来这 3 点被算进了技能等级。
- **奖励专长**：属性块的专长常含职业、模板、种族给的奖励专长，超过「生命骰/2 + 神话」的部分写进角色的「奖励专长公式」，专长栏不再显示超额。
- **武器进战斗栏**：PF1 的武器只有 `showInCombat` 打开才在战斗栏出现，原来属性块里的武器攻击都只在物品栏。现在所有武器都打开。
- **能力分栏**：怪物能力默认是种族特性；职业来的（职业能力、进阶职业、变体）和神话能力（神话之力、神话不朽……）是职业能力；专长照旧；杂项只留「属性块修正」。种族生命骰自动带的黑暗视觉等也改成种族特性。

## 和 Roll Bonuses 共存（2026-10-18，1.0.1）

Roll Bonuses（ckl-roll-bonuses 2.23）怎么认物品：看 `system.flags.boolean` 的键（spell-focus、weapon-focus……），没有键的，在建物品（preCreateItem）或打开物品表时按名字/来源 id 自动补键，并替用户选学派或武器（`flags.ckl-roll-bonuses`）。要选项的加值（专攻、专精、精通重击、元素专攻）没选项就不加；**武器娴熟**（`bonus_finesse` + `target_finesse`）不用选项，出手时把用力量的天然攻击和灵巧武器的公式里的力量换成敏捷（敏捷更高、公式里还没有敏捷时）。
- 1.0.0 的问题：攻击是在装着 Roll Bonuses 的 test3d 里补差的，补差算进了它的力量→敏捷替换，所以**纯 PF1 里有武器娴熟的怪攻击偏低**（少敏捷与力量之差，猫、蝮蛇少 6）。以前的全量核对只核了 HP/AC/豁免等，没核攻击，没发现。
- 修法（`build_actor.js`）：`finesseDexUpdates` 把这些攻击直接改用敏捷，再 `attackAdjust` 按属性块补差（补差改成加在原值上，原来是覆盖，只对新建攻击成立）。纯 PF1 和 Roll Bonuses 结果一样。`rbKeys` 按来源条目预先写上 Roll Bonuses 的键（`RB_KEYS`，30 个来源），不写选项：纯 PF1 不认这些键，Roll Bonuses 看到有键就不再自动配置。
- 用户不要在这些专长上给 Roll Bonuses 选武器/学派，加值已经在数值里。
- `zh-monsters/attack_pass.js`：干净世界全量攻击核对（dry）/ 修正（fix）。`zh-monsters/rb_finesse_test.js`：在装着 Roll Bonuses 的世界里正式使用攻击，核对加值。

## 下次全量重建的做法（2026-10-17 定）

现在的 `batch.js runAll` 每只怪要和服务器来回 30–60 次，每次 PF1 都把整只怪重算一遍，约 2.5 秒一只，全部要两个多小时，面板隐藏或页面刷新就会断。下次规则改了要全部重建时，先改成：

1. **离线生成**：Python（接着 `plan.py`）把每只怪写成一份静态 JSON，这个文件夹就是唯一的源（可 diff，只重新生成改动的）。`build_actor.js` 里拼物品的部分（复制条目、种族、标识符、技能专攻、战斗栏、能力分栏、职业自动带的特性）搬过来。
2. **Foundry 里只校准一次**：读入 JSON，建不存盘的临时角色，让 PF1 算完，补差值（技能等级、职业 HP、豁免进度、属性块修正、能力基础值、奖励专长公式）写回 JSON。攻击核对改成直接读系统算好的攻击加值，不发攻击卡。
3. **离线打包**：`fvtt package pack`（foundryvtt-cli），打包时 Foundry 不能占着这个包。

切换前先拿几十只样本新旧两种方式各建一次，结果完全一致再全量切。零星修几只仍可用 `fixup`。
